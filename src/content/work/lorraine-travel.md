## The challenge

Lorraine Travel is a travel advisory business that plans luxury travel. Its website has years of content and links behind it, and that history has value: pages that other sites link to, and pages that search engines already know.

A redesign can throw that value away. Change the URLs without a plan, drop a page that still receives visits, or bury the services under a new layout, and the site looks better while performing worse. The task was to modernize the experience and keep what already works.

## My contribution

I am developing the modernized website. My work covers the front-end build in HTML, CSS and JavaScript, the site architecture, technical SEO, structured data, luxury travel content, and the places where the website can connect to marketing tools and automation.

This is development and staging work. The redesigned site is not presented here as publicly launched, and the link above goes to the current live website.

## The solution

I started with an inventory of the current site: which pages exist, which carry important content, and which links must keep working. That inventory decides the new structure, so the architecture follows the content the business already has instead of a template.

From there the work falls into four parts:

- **Architecture.** Services and destinations arranged in a clear hierarchy, with each page reachable through navigation and contextual links.
- **Positioning.** Service pages that say plainly what the advisory does and who it is for.
- **Search-friendly pages.** Descriptive titles and headings, internal links, and structured data that reflects what is on the page.
- **Conversion pathways.** A visible next step on each page, so a reader interested in a trip knows how to start a conversation.

The build is an example of my [website development](/services/website-development/) approach: search and performance decisions made while the pages are written, not added afterward.

## Technical implementation

The site is hand-built in HTML, CSS and JavaScript and prepared for Cloudflare Pages. Static pages load quickly, cost little to host and have few moving parts to maintain. JavaScript is used where a page needs it and left out where it does not.

For search, each page gets its own metadata and a logical heading structure. Existing URLs are mapped to their new equivalents so that redirects can be put in place where a path changes. Structured data is added as JSON-LD and limited to facts the page shows.

I also noted where the site could connect to other systems, such as inquiry forms feeding a CRM and follow-up handled through [workflow automation](/services/automation/). Those are identified opportunities, not finished integrations.

## Outcome

What exists today is a modernized build in development: a new page structure, redesigned templates, search-oriented page content, and a deployment path through Cloudflare Pages. The important existing content and links have been accounted for in the new structure.

Because the redesign has not been launched, there are no live results to report, and I have not published performance figures for this project.

## Considerations

The main trade-off was between a clean slate and continuity. Starting over would have been faster to design. Keeping existing content and links took more planning and protects what the site has already earned.

Choosing plain HTML, CSS and JavaScript over a heavier framework was deliberate. It keeps the site fast and inexpensive to run, and it means content updates need someone comfortable with code, or a simple editing process agreed before launch. That question is still open and belongs on the launch checklist, along with redirect testing on the staging build.
